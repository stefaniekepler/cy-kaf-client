# 全部集群返回入口体验优化设计

- 日期：2026-09-04
- 状态：用户已批准推荐方案
- 范围：左侧导航、集群列表页文案、相关前端与端到端测试、本机桌面打包安装验证

## 1. 问题与目标

左侧导航首项当前显示 `Dashboard`，但它实际承担的不是个性化仪表盘职责，而是返回全部
集群列表，并从该列表进入新增集群流程。用户在单个集群的管理页中无法仅凭
`Dashboard` 判断该入口会返回集群列表，已有多位用户因此难以找到新增 Cluster 的入口。

本次优化的首要目标是让用户明确知道如何返回全部集群列表。新增入口继续位于集群列表
页，不在每个管理页增加常驻 CTA，避免改变现有操作层级和侧栏视觉重心。

验收结果应满足：

- 用户在任一集群管理页都能从侧栏直接识别并进入全部集群列表；
- 全部集群入口与具体集群菜单在视觉层级上可区分；
- 到达列表页后，用户仍能按现有权限与动态配置规则看到 `Configure new cluster`；
- 不改变现有路由、数据请求、权限规则、集群菜单行为或移动端侧栏行为。

## 2. 方案比较

### 方案 A：明确命名的全局入口（采用）

将侧栏首项从 `Dashboard` 改为带概览图标的 `All clusters`，并将列表页标题同步改为
`Clusters`。在首项上方增加低对比度的 `Overview` 分组标签，在具体集群列表上方增加
`Clusters` 分组标签，使全局入口与单集群管理入口的层级一眼可见。

该方案沿用原入口的位置、点击范围、圆角、颜色和选中态，只改善语义与层级，最符合
“清楚但不破坏整体 UX”的约束。代价是需要同步修改用户可见文案及相关测试。

### 方案 B：强动作式返回入口

将首项改为 `← Back to clusters`。返回含义最强，但常驻入口更像临时返回按钮，而不是
稳定的全局导航目的地；用户已在列表页时语义也不自然，因此不采用。

### 方案 C：内容区面包屑

保留 `Dashboard`，在各资源页标题上方增加 `All clusters / <cluster> / <resource>`。
它可以表达完整层级，但需要改动全部资源页，且没有消除侧栏原入口的歧义，超出本次
最小范围，因此不采用。

## 3. 导航与视觉设计

侧栏保持现有宽度、内边距、字体、圆角和主题色。导航自上而下排列为：

1. 低对比度、小字号的 `Overview` 分组标签；
2. 带概览图标的 `All clusters` 全局入口；
3. 低对比度、小字号的 `Clusters` 分组标签；
4. 现有各集群折叠菜单及其资源子项。

概览图标是装饰性图标，使用 `currentColor` 跟随普通、悬停、激活及深色主题状态，并对
辅助技术隐藏。`All clusters` 保留完整可访问文本，不依赖图标表达含义。

`All clusters` 链接继续指向现有首页路由。当前地址精确为 `/`、`/ui` 或
`/ui/clusters` 时，该项使用现有紫色激活样式；在单个集群及资源页中不激活。点击后仍
由 React Router 进行客户端导航，不增加返回栈或重定向逻辑。

全部集群列表页的主标题从 `Dashboard` 改为 `Clusters`。在线/离线指标、筛选开关、
表格、行点击行为及 `Configure new cluster` 的位置与样式保持不变。

## 4. 组件边界与数据流

- `Nav` 负责分组标签、全部集群入口、首页路由激活判断及现有集群菜单排列。
- `MenuItem` 增加可选的前置图标输入，并继续提供链接、点击区域和主题状态；现有未传
  图标的集群资源项保持当前渲染，不把首页路径判断下沉到通用菜单项。
- 新概览图标放入现有公共图标目录，保持单一视觉职责，不读取路由或业务状态。
- `Dashboard` 组件只调整页面标题；集群查询、离线筛选、权限判断和新增按钮逻辑不变。

数据流不变：`useClusters` 仍提供侧栏及列表数据，`useGetUserInfo` 与
`GlobalSettingsContext` 仍共同决定新增按钮是否可用。导航优化不发起新的 API 请求，也
不缓存新的用户数据。

## 5. 错误处理与兼容性

本次不新增异步流程。集群加载或用户信息查询失败时，继续使用现有 React Query 全局
错误处理和页面状态。入口本身始终可见，因此即便集群列表为空或加载失败，用户仍能
识别全部集群这一全局位置。

三个既有首页地址继续有效，已有书签和深链接不受影响。动态配置关闭或用户没有应用
配置权限时，`Configure new cluster` 仍按原逻辑隐藏或禁用；导航文案不会暗示用户一定
拥有新增权限。

## 6. 测试与验收

### 自动化测试

- 导航组件测试覆盖 `Overview`、`All clusters`、`Clusters` 分组标签及概览图标；
- 在 `/`、`/ui`、`/ui/clusters` 上断言全部集群入口激活，在单集群路由上断言不激活；
- 断言 `All clusters` 仍链接到现有首页，集群菜单数量和内容不回退；
- Dashboard 测试断言标题为 `Clusters`，并保持新增按钮的动态配置与权限行为；
- 更新端到端导航场景中的用户可见文案，验证从集群页点击 `All clusters` 后显示
  `Clusters` 标题并到达全部集群路由；
- 运行前端相关 Jest 测试、前端完整测试、lint/type check 和生产构建。

### 本机桌面验证

在当前 macOS 主机使用本机 Rust target 生成 `.app` 与 `.dmg`。执行仓库已有桌面冒烟
脚本后，从新生成的 DMG 安装 `Cy KafClient.app` 到 `/Applications`。若目标位置已有
旧版本，先将旧应用移动到废纸篓中的唯一时间戳路径，确保可恢复，再复制新版本；不使
用递归删除清理旧应用。

启动已安装应用并人工检查亮色与深色主题下的以下流程：

1. 在单集群页面看到分组清晰的 `All clusters`；
2. 点击后到达全部集群列表，入口进入激活态且标题显示 `Clusters`；
3. 有权限且启用动态配置时仍能看到并进入 `Configure new cluster`；
4. 侧栏折叠/展开、集群菜单和窄窗口覆盖层行为没有回退。

记录生成包路径、安装路径、冒烟结果及人工验收结果。若当前主机缺少签名身份，使用仓库
既有的临时签名/未签名本机构建方式，不把签名问题误判为本次导航回归。

## 7. 非目标

- 不把新增 Cluster 按钮常驻到侧栏或顶部导航；
- 不新增面包屑、集群切换器或新的首页路由；
- 不重命名内部 `Dashboard` 组件或 API；
- 不调整集群配置表单、权限模型、数据模型或后端实现；
- 不进行与导航语义无关的样式重构。
