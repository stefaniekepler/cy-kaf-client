# 全部集群入口柔和强调与返回提醒设计

- 日期：2026-09-05
- 状态：用户已批准方案 A
- 范围：`All clusters` 常驻底色、进入集群时的中文锚点提醒、响应式与无障碍行为、相关测试及本机安装验收
- 最终调整（2026-09-06）：移除冗余的 `Overview` 分组标签；提醒保留标题，并改用明暗主题自适应的低饱和灰蓝中性色 token

## 1. 问题与目标

侧栏首项已经由含义模糊的 `Dashboard` 调整为 `All clusters`，单集群资源保留在
`Clusters` 分组中；最终方案移除了冗余的 `Overview` 标签。用户反馈入口在当前中性色侧栏
中仍不够醒目，进入集群后依然可能忽略它，进而难以返回全部集群列表并找到新增集群入口。

本轮优化需要同时提供两类线索：

- 以极浅常驻底色提高 `All clusters` 的持续可发现性；
- 用户每次从集群外进入集群时，以中文锚点提醒明确说明该入口的职责。

提醒必须柔和、短暂且不阻断操作，不把全局入口做成突兀的主按钮，也不改变现有侧栏的
布局重心、灰阶色调、集群导航逻辑或新增集群权限规则。

## 2. 方案比较

### 方案 A：锚点式轻提示（采用）

给 `All clusters` 增加极浅常驻底色，并在进入集群时于入口右侧展示小型悬浮提示。提示与
目标入口相邻，用户能直接建立“这里可以返回”的空间认知；悬浮层不挤动侧栏内容，约四秒
后自动淡出。

代价是提示短暂覆盖主内容区左上方的一小块区域。通过限制宽度、使用低对比度阴影且不
接收交互，可将影响控制在最低程度。

### 方案 B：侧栏内嵌提示

将帮助文案临时插入 `All clusters` 下方。信息完全留在导航区域，视觉最安静，但出现与
消失会推动集群菜单，产生不必要的布局移动，因此不采用。

### 方案 C：内容区轻量 Toast

在内容区顶部显示提示，不改变侧栏排版，也符合常见系统反馈形式。但提示与实际入口距离
较远，用户较难建立位置记忆，因此不采用。

## 3. 视觉与文案

`All clusters` 常态增加极浅的中性色背景与细边框。亮色主题使用低透明度深色，深色主题
使用低透明度浅色；悬停和激活态按同一色系逐级轻微加深。不引入高饱和强调色，也不改变
入口现有字号、字重、圆角、图标或点击区域。

进入集群后的提醒锚定在 `All clusters` 入口右侧，带有朝向入口的小箭头。提醒使用主题
专属的 `allClustersReminder` 低饱和灰蓝中性色背景、边框、两级文字和低强度阴影，并分别
适配明暗主题。宽度以两至三行中文为上限，不使用警告色、成功色、插画或醒目图标。

提醒文案固定为：

- 标题：`返回全部集群`
- 正文：`点击左侧 All clusters，可返回并添加或管理集群。`

提醒约四秒后自动淡出。淡入淡出时长控制在 160–200 毫秒；系统启用“减少动态效果”时
取消位移或缩放，只保留即时显示与隐藏。

## 4. 触发与生命周期

“进入集群”定义为路由状态从不包含集群上下文变为包含集群上下文，包括：

- 从全部集群列表点击一行进入集群；
- 从其他全局页面或入口进入集群；
- 应用首次启动或直接打开集群深链接。

以下情况不重复触发：

- 在同一集群内切换 `Brokers`、`Topics`、`Consumers` 等资源页；
- 从一个集群资源页直接切换到另一个集群资源页；
- 提醒仍在展示时发生集群内部重定向。

用户离开集群上下文后，当前提醒立即消失并恢复待触发状态。下一次从集群外进入任意集群
时重新展示。点击 `All clusters` 返回列表时也立即隐藏。

由于每次进入都会提醒，首次使用和版本升级后的首次进入自然被覆盖，不记录
`localStorage`、Cookie 或版本标记，也不增加跨会话状态。

## 5. 响应式与无障碍

宽屏侧栏可见时，提醒在触发后立即展示并开始四秒计时。窄屏进入集群后侧栏默认收起，
此时只记录一个待展示状态，不启动计时；用户打开侧栏后再展示提醒并开始计时，避免提示
在不可见区域中静默过期。提醒一旦可见，仅在本次进入周期展示一次，关闭并重新打开侧栏
不会重复开始一轮提醒。

提醒不抢占键盘焦点、不拦截入口点击，并使用 `role="status"` 与
`aria-live="polite"` 宣读中文内容。装饰箭头对辅助技术隐藏。`All clusters` 原有可访问
名称、`aria-current` 和激活类保持不变；常驻底色不能成为识别当前页面的唯一依据。

## 6. 组件边界与状态流

- `PageContainer` 已掌握当前路由和侧栏展开状态，负责识别“集群外 → 集群内”的边界、
  保存本次进入周期的待展示/已展示状态，并将是否可见传给导航。
- `Nav` 继续负责 `All clusters` 的路由、激活判断与排列，并在入口旁渲染独立的
  `AllClustersReminder`。
- `AllClustersReminder` 只负责中文内容、锚点视觉、四秒计时、淡出及卸载清理；它不读取
  集群数据、不导航，也不持久化状态。
- `MenuItem` 只增加一个可选的轻强调样式输入。默认值保持关闭，因此所有现有集群标题和
  资源菜单继续使用原来的颜色与交互状态。

状态流为：路由进入集群 → 标记提醒待展示 → 侧栏可见 → 展示并启动计时 → 四秒后淡出并
标记本次已展示。离开集群会取消未完成的计时并重置进入周期。组件卸载时始终清理计时器，
避免卸载后更新状态。

## 7. 错误处理与兼容性

本次不增加网络请求、Kafka 查询或后端依赖。集群列表、权限信息或业务请求失败时，继续
使用现有错误处理；提醒仍只根据路由上下文工作，不因接口错误阻断导航。

首页别名、集群深链接、浏览器历史、动态配置开关和 `Configure new cluster` 权限判断均
保持不变。现有 `MenuItem` 调用方不传轻强调参数时，DOM 语义、背景、悬停与激活行为均
不变化。

## 8. 测试与验收

### 自动化测试

- 断言 `All clusters` 在普通、悬停和激活状态使用专属的柔和主题底色，其他菜单项不受
  影响；
- 断言提醒使用固定中文标题和正文，并具有 polite live region；
- 使用伪计时器验证提醒约四秒后消失，以及卸载、离开集群和点击返回时清理计时器；
- 覆盖首次直接进入集群、从列表进入、集群内部切页、集群间直接切换、离开后再次进入；
- 覆盖宽屏立即展示、窄屏侧栏收起时等待、展开后开始展示且同一进入周期不重复；
- 验证首页精确激活、尾斜杠别名、现有集群菜单 active class 和新增集群按钮权限没有回归；
- 运行相关 Jest 测试、完整前端测试、lint、TypeScript、生产构建及仓库完整验证。

### 本机桌面验收

重新生成本机架构的 `.app` 与 `.dmg`，校验 DMG 与应用签名后覆盖安装到
`/Applications/Cy KafClient.app`；覆盖前继续保留可恢复的旧应用备份。

启动已安装应用并验证：

1. 从全部集群列表进入集群时，提醒紧邻 `All clusters` 显示中文文案；
2. 提醒约四秒后自动消失，集群内部切页不再次出现；
3. 返回列表再进入集群时重新出现；
4. 点击 `All clusters` 返回 `Clusters` 列表，激活态恢复；
5. 亮色、深色及窄窗口下底色和提醒保持柔和、清晰且不遮挡关键操作。

若宿主机仍未授予屏幕录制权限，不生成或提交无效桌面截图；使用已安装应用的原生可访问
性树、路由状态和 smoke 结果作为验收证据，并如实记录视觉截图限制。

## 9. 非目标

- 不把 `All clusters` 改成高饱和主按钮；
- 不使用需要手动关闭的 Banner、Modal 或阻断式新手引导；
- 不在集群内部每次切换资源页时重复提醒；
- 不新增提醒设置、频率配置或跨会话持久化；
- 不调整集群数据、配置表单、权限模型、后端 API 或 Kafka 连接；
- 不借此重构其他菜单项、响应式侧栏或全局通知系统。
